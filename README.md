## a. Problem Statement

A Security Operations Center (SOC) monitoring an enterprise network receives
a continuous stream of network connection records and needs to know, for
each one: *is this normal traffic, or an attack — and if it's an attack,
what kind?* Manually inspecting every connection does not scale.

This project builds and compares 5 supervised classification models that
take a network flow's statistical fingerprint (duration, byte/packet
counts, rates, TTLs, connection-state, protocol/service, etc.) and predict
which of **10 traffic categories** it belongs to: `Normal`, or one of 9
attack types — `Generic`, `Exploits`, `Fuzzers`, `DoS`, `Reconnaissance`,
`Analysis`, `Backdoor`, `Shellcode`, `Worms`. This is effectively the core
ML component behind a real Network Intrusion Detection System (NIDS): an
automated first pass that flags and categorizes suspicious traffic so a
human analyst can prioritize response.

## b. Dataset Description

**Source:** [UNSW-NB15](https://research.unsw.edu.au/projects/unsw-nb15-dataset)
— a network intrusion dataset created by the UNSW Canberra Cyber Range,
combining real normal network traffic with traffic generated by real
attack tools. This repo uses the dataset's standard pre-extracted
"training partition" (`data/UNSW_NB15_full.csv`).

| | |
|---|---|
| Rows (full dataset) | 175,341 |
| Columns | 45 (`id`, 42 features, `label`, `attack_cat`) |
| Target | `attack_cat` — **10 classes** (multiclass) |
| Task | Multiclass classification |
| Missing values | None |

**Why 42 features, not 44:** `id` (row identifier) and `label` (a binary
attack/normal flag) are dropped before modeling — `label` is derived
directly from `attack_cat` (0 only when `attack_cat == "Normal"`), so
using it as an input feature would leak the answer.

**Feature groups actually used:**
- **Flow basics:** `dur`, `proto`, `service`, `state`, `spkts`, `dpkts`, `sbytes`, `dbytes`, `rate`
- **TTL / window / sequence:** `sttl`, `dttl`, `swin`, `dwin`, `stcpb`, `dtcpb`
- **Timing:** `sinpkt`, `dinpkt`, `sjit`, `djit`, `tcprtt`, `synack`, `ackdat`
- **Loss / load:** `sloss`, `dloss`, `sload`, `dload`
- **Content:** `smean`, `dmean`, `trans_depth`, `response_body_len`
- **Connection-history counters:** `ct_srv_src`, `ct_state_ttl`, `ct_dst_ltm`, `ct_src_dport_ltm`, `ct_dst_sport_ltm`, `ct_dst_src_ltm`, `ct_ftp_cmd`, `ct_flw_http_mthd`, `ct_src_ltm`, `ct_srv_dst`
- **Flags:** `is_ftp_login`, `is_sm_ips_ports`

**Class distribution (full dataset) — note the real-world imbalance:**

| Class | Count |
|---|---|
| Normal | 56,000 |
| Generic | 40,000 |
| Exploits | 33,393 |
| Fuzzers | 18,184 |
| DoS | 12,264 |
| Reconnaissance | 10,491 |
| Analysis | 2,000 |
| Backdoor | 1,746 |
| Shellcode | 1,133 |
| Worms | 130 |

**Preprocessing (see [`model/preprocessing.py`](model/preprocessing.py)):**
1. Drop `id`, `label`.
2. `proto` has 133 distinct values; the long tail is bucketed into
   `"other"`, keeping only the 6 most frequent (`tcp`, `udp`, `unas`,
   `arp`, `ospf`, `sctp`) as their own categories — otherwise one-hot
   encoding would create 130+ mostly-empty columns.
3. One-hot encode `proto`, `service`, `state`; standard-scale all numeric
   features (fit only on the training split, via a `ColumnTransformer`
   inside each model's `Pipeline`).
4. **Class-stratified subsampling for training/evaluation speed:** every
   class is capped at 6,000 rows; classes already smaller than the cap
   (Analysis, Backdoor, Shellcode, Worms) are kept in full. This keeps
   the dataset's real imbalance intact (Normal is still ~46× more
   frequent than Worms) while making training and Streamlit-Cloud
   inference fast. Result: **41,009 rows**, split 85/15 into train
   (34,857 rows) and test (6,152 rows, stratified) — the test split is
   saved as [`test_data.csv`](test_data.csv).

**Note on metric averaging:** Precision, Recall, and F1 are **macro-averaged**
across all 10 classes (each class counted equally), not weighted by class
size — otherwise the score would be dominated by the large `Normal`/`Generic`
classes and say nothing about how well the model catches rare attacks like
`Worms`. AUC is computed one-vs-rest, macro-averaged.

## d. Models Used

All 5 models are trained on the same preprocessed dataset
(see [`model/train_models.py`](model/train_models.py)):

1. Logistic Regression
2. Decision Tree Classifier
3. K-Nearest Neighbor Classifier (k=15)
4. Naive Bayes Classifier (Gaussian)
5. Random Forest Classifier (Ensemble, 150 trees)

### Comparison Table

|---|---|---|---|---|---|---|
| Logistic Regression | 0.6725 | 0.9232 | 0.6861 | 0.4924 | 0.4980 | 0.6271 |
| Decision Tree | 0.7391 | 0.9026 | 0.7566 | 0.6663 | 0.6764 | 0.7071 |

### Observations

| ML Model Name | Observation about model performance |
|---|---|
| Logistic Regression | Solid AUC (0.923) shows it ranks classes reasonably well, but its linear decision boundary can't cleanly separate 10 overlapping attack types — recall (0.49) lags precision (0.69) noticeably, meaning it consistently misses attack instances (especially minority classes) rather than false-alarming on them. |
| Decision Tree | Strong, well-rounded performance (2nd best on Accuracy, Precision, Recall, F1, MCC) — a single tree can carve non-linear, axis-aligned splits that suit this feature mix well, and depth-capping (max_depth=15) kept it from badly overfitting despite having no ensembling to smooth variance. |
| kNN | Middling across all metrics. Distance-based classification is hurt by the high-dimensional one-hot-encoded feature space (curse of dimensionality) and by class imbalance — a query point's neighborhood is dominated by common classes (Normal/Generic/Exploits), pulling predictions away from rare attacks like Worms and Shellcode. |
| Naive Bayes | Clearly the weakest model (Accuracy 0.34, F1 0.27) despite a not-terrible AUC (0.82). Gaussian Naive Bayes assumes features are conditionally independent and normally distributed given the class — both assumptions are badly violated here (e.g. `sbytes`/`dbytes`/`sload`/`dload` are highly correlated and heavily right-skewed), so while it can still rank classes somewhat by likelihood, its hard classifications and calibration are poor. |
| Random Forest (Ensemble) | **Best model overall** — highest Accuracy (0.746), AUC (0.944), Precision (0.813), and MCC (0.716). Averaging 150 decorrelated trees smooths out the overfitting/variance issues of the single Decision Tree while still handling the mixed categorical/numeric features natively. Its recall (0.619) is a bit more conservative than the Decision Tree's — it trades a little sensitivity to rare attacks for much higher precision (fewer false alarms), a typical and generally favorable ensemble trade-off for a SOC alerting use case. |
| **Overall Winner for your dataset?** | **Random Forest (Ensemble)** — it leads on AUC and MCC, the two most trustworthy metrics for a 10-class problem this imbalanced (AUC is threshold-independent; MCC accounts for all four confusion-matrix quadrants across classes, unlike raw Accuracy which is inflated by the large Normal/Generic classes), and it also has the best Precision. Decision Tree is the strongest runner-up and clearly outperforms Logistic Regression, kNN, and Naive Bayes on every metric except AUC. |
